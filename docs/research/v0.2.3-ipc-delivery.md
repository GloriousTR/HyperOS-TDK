# v0.2.3 IPC Delivery Evidence

Target device log from 2026-08-20 showed:

- HyperOS TDK v0.2.2 installed (`versionCode=9`).
- Theme Manager process loaded the module under Vector API 102.
- Readiness passed `10/10`.
- `CONTROLLED IMPORT BRIDGE READY: protected URI receiver registered in Theme Manager process.` appeared.
- The Android document picker returned to `ModuleStatusActivity` and two subsequent user taps occurred (controlled import button + confirmation).
- No `CONTROLLED IMPORT IPC`, `URI staged`, `REQUEST accepted`, or ThemeImportManager invocation log appeared afterward.

Therefore the v0.2.2 failure is before URI staging: the control broadcast is not reaching the dynamic receiver.

v0.2.3 changes the IPC boundary:

1. Removes the custom signature-permission filter from the dynamically registered receiver.
2. On Android 14+ verifies the actual broadcast sender with `BroadcastReceiver.getSentFromPackage()` / `getSentFromUid()` and confirms the UID owns `com.glorious.hyperostdk`.
3. The sender explicitly calls `grantUriPermission(com.android.thememanager, uri, FLAG_GRANT_READ_URI_PERMISSION)` and verifies the grant against Theme Manager's UID before broadcasting.
4. The sender logs grant verification, broadcast dispatch, and delayed grant revocation under `HyperOS-TDK-App`.
5. Theme Manager logs the received sender package/UID before staging.

No import is triggered automatically; the existing explicit user confirmation remains required.
